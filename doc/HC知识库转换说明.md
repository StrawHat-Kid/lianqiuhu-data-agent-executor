# HC 纯问数知识库转换说明（v2）

## 最终采用结构

执行器 `knowedge/` 只放生产知识：

1. `00_HC知识库规则.md`
2. `01_HC专题指标快照.csv`（308 条）
3. `02_HC月度指标.csv`（36 条）
4. `03_HC能耗日度.csv`（124 条）
5. `04_HC运营日度.csv`（93 条）
6. `05_HC小时指标.csv`（146 条）
7. `06_HC事件与告警.csv`（35 条事件）

前五张事实表合计 **707 个唯一 fact_id**，没有重复 fact_id。

## 为什么以方案 ZIP 为主，而不是 Excel v1

Excel v1 共 926 条指标，但时间槽位在转换时丢失：大量不同日/月/小时值被写成同一个 `2026-09-11`。其中 28 组、628 行形成同业务键多值歧义。因此 Excel 适合人工盘点，不适合直接作为模型知识源。

ZIP 中原始 CSV 保留：
- `scenario_id`
- `period_label` / `time_label`
- `category`
- `aggregation`
- `data_flag`

这些字段对纯问数的唯一定位更关键。

## 为什么不把 ZIP 全量文件直接塞入 knowedge

原 ZIP 包含大量重复视图：

- `练秋湖_能耗数据_小时级.csv` 的 53 个 fact_id 已全部包含在 `练秋湖_小时指标.csv`。
- `练秋湖_资产设备汇总.csv`、`练秋湖_通行会议网络汇总.csv` 的事实已被核心事实表覆盖。
- 大 Markdown 文件再次展开了全部事实、问答覆盖和字典。
- `练秋湖_问答覆盖表.csv` 对 707 条事实逐条生成问法，属于回归数据，不应重复注入。
- `练秋湖_数据字典.csv` 适合审计，不必进入每次模型上下文。

因此生产 knowledge 只保留不重复的核心事实与事件。

## 为什么 Gold Set 不进入生产 knowledge

Gold Set 有代表性，但存在明显质量疑点，例如：
- “水冷机组有多少台？”对应标准答案却是“可用度为98%”；
- 部分“数量”问法对应百分比或异常单位。

为了避免错误问答模板污染模型，v2 将 Gold Set 放入 `validation/`，不进入 `knowedge/`。

## 当前数据质量待确认

详见 `validation/HC数据质量待确认项.csv`。

重点包括：
- 人车数量统计同指标多场景不同值；
- 用气/用水/年度节能等单位疑点；
- 相对系统时间与绝对日期之间没有完整历史映射。

## 集成方式

将本包 `knowedge/` 的 7 个文件复制到：

`lianqiuhu-data-agent-executor/knowedge/`

有正式知识文件后删除 `.gitkeep`。

`validation/` 建议放在项目独立验证目录（例如 `testdata/` 或 `doc/validation/`），**不要**放入 `knowedge/`，否则执行器会把它们一起全文注入模型。

## Prompt 最小增强

核心 Python 无需修改，但 `config.json` 和 `config.example.json` 的 `system_prompt` 应最小补充：

- 所有数值均为模拟演示数据，业务数值回答必须声明“以下基于模拟演示数据”；
- 不得编造、不得推断根因/责任/结论；
- 严格区分时间槽位、分类条件、当期/累计；
- 同语义多场景出现不同值时列出候选，不得任意选一个；
- 无法唯一映射的绝对历史日期应明确说明无法确认。

## 验收建议

第一轮不建议直接跑 707 条在线模型回归。

建议：
1. 先做结构校验（707 fact_id 唯一、数据文件可读）。
2. 再选 20~30 条高质量样本覆盖固定/月/日/小时/事件/冲突场景。
3. Gold Set 仅使用人工确认过的样本。
4. 数据口径确认后，再决定是否扩大在线回归。
